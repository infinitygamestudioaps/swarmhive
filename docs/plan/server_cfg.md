## How to open it

- Board: _bbshome -> Cabinet -> Settings (the page arrives as an NPC-style dialog, OnNpcHtmlMessage). The bots use this path (`cabinetSet`). The live Cabinet menu is Autopotion · Restore character · Character info · Settings. The 2020 Home menu also had Commands (= .help), Premium Account, Professions and Subclass.
- Chat: .cfg (GUIDE: the same page; untested by the bots).
- Clicking: Buttons are "bypass -h 0x": send the code WITHOUT "-h " (e.g. "0c") or nothing happens (CLAUDE.md §2d). No Carrier: "010 <number>" (INFERRED: the client replaces $set with the edit box text).
- Matching: Match a row by section + label (cfgFind), never by code and never by a bare "Party" / "Master Account" / "Same IP" (two sections share them).

## What our bots set today

- `Block experience`: the level lock (`levelCtlTick` → `expBlockSet` → `cabinetSet('Block experience')`) sets it from `Scripts/data/level_control.json` (dashboard Circuit → Levels). The cfg defaults never touch it.
- `Forward Drop to Party Leader`: the user decides this with `!cabinet Forward Drop on|off` (Off 2026-10-03, On again 2026-10-04). It is On on every captured character.
- Quick Trade (Master Account / Party / Same IP) and Quick Accept: Claude switched them on by hand for the first 12 on 2026-10-03 (user OK). The later characters had the server defaults, which are the same except Quick Trade: Party.
- Follow Party Leader's Dialog / .town / Dead to Village: server default On, and the travel design relies on them (CLAUDE.md §2d). Nothing re-checks them today; `!cfg` (patch) reports them.
- `.autohp/.automp/.autocp`: not used. swarm.js has its own survival loop (Mana Potion 728, Healing Potion 1061, self heals), and L2Swarm AutoItem is in the XML.
- `.townname`: used for every town trip (`townCommand`, 11 towns).

## Bot automation (patch_servercfg.js, NOT applied)

- **cabinetSet fix:** rows are found with `cfgFind` (key, "Section: Label", alias, then exact > prefix > contains). An ambiguous text is refused and nothing is clicked. Before the fix, `!cabinet Party off` turned OFF Follow Party Leader's Dialog.
- **`!cfg [name]`:** reads the page and reports in party chat. It writes `Logs/servercfg_<Name>.json` with the values and the diff against `botDefaults.want`. It changes nothing.
- **`!cfg apply [name]`:** sets every `botDefaults.want` row that differs (each click is verified on the page the server returns). This is an explicit order, so it works with autoApply off.
- **Auto-apply:** only when `botDefaults.autoApply` is true (default **false**). It runs once per script start, `startDelayS` (120 s) after the character is ready, then every `verifyHours` (12 h); a failure waits 15 min. It never runs while dead, fighting, in a raid or mission, trading, or using a gatekeeper or the board. `onlyChars` / `skipChars` limit it. `trial` rows are NOT applied by auto-apply, only listed.
- Dashboard: the `!cabinet` suggestions now name the section ("Quick Trade: Party"). Command center (2026-10-12 evening): the entries **Server settings (.cfg): report** (`!cfg [name]`, safe) and **Server settings (.cfg): apply the bot defaults** (`!cfg apply [name]`, confirm; category Party) are ready in the scratchpad `catalog_pending.json`; `node catalog_pending.js` adds them to `Dashboard/commands.js` right AFTER patch_servercfg.js is applied to Scripts_dev/swarm.js (catalog rule: never list a command swarm.js does not handle), then regenerate docs/plan/dashboard_commands.md and restart the dashboard server.
- Reviewed 2026-10-12 evening: auto-apply stays **off** (`autoApply: false`). The `want` rows already match on all 36 captured characters except Quick Trade: Party (Off on 27, harmless while Same IP is On), so the explicit `!cfg apply` is enough; `trial` rows (Do not show traders, Disable Animations) are only reported. Block experience is never touched (level lock), Forward Drop never (user decision). Apply order with the other patches: see the guides report (patch_servercfg.js first).
